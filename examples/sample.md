## 1. 背景

社内の備品管理ツール「ミドリ」では、**貸出記録の検索が遅い**という課題がありました。`items` テーブルに索引がないことが原因です。詳しくは [設計資料](https://example.com/midori/design) を参照してください。

### 1.1 現状の課題

- 貸出記録の検索に平均 3 秒かかる
- 一覧画面の表示が 1,000 件を超えると重くなる
- 返却期限の通知メールが重複して届く

### 1.2 対応の手順

1. 検索条件の利用状況を調べる
2. 索引を追加する
3. 通知処理を見直す
4. 負荷試験で効果を確認する

- [x] 利用状況の調査

## 2. 設計方針

> 速さよりも、まず正しさを保つ。
> 変更は小さく、確認しやすい単位で行う。

検索処理は次のように書き換えます。

```go
func Search(db *sql.DB, keyword string) ([]Item, error) {
	rows, err := db.Query(
		"SELECT id, name FROM items WHERE name LIKE ?",
		"%"+keyword+"%",
	)
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	return scanItems(rows)
}
```

## 3. 効果の見込み

| 項目 | 現状 | 目標 |
|---|---|---|
| 検索時間 | 3.0 秒 | 0.3 秒 |
| 一覧表示 | 2.5 秒 | 0.5 秒 |
| 通知の重複 | あり | なし |
